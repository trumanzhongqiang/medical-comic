# 事实核查（先于分镜）

医学论断先过这一关，再写进 `script.json` 的 `beats`。画面可以朴素，知识错了传播越广伤害越大。自动质检（`audit.py` / `qacheck.py`）查不了医学对错，本文件是人工核查关卡。

每个核心知识点都要检索核对权威来源：教科书、诊疗指南、WHO、国家卫健委、专业学会指南、可核验的论文。数字、单位、因果关系必须精确。

## 1. 知识卡

每个知识点留一张卡，随 `script.json` 的 `sources` 留档：

- **结论**：一句话，观众能复述。
- **来源**：单一可核验出处（机构 + 文件名 + 年份或版本；有页码或条款就写上）。
- **类比**：一句话，以及它在画面里怎么被看见。比喻之后必须补回真实机制。

## 2. 缺口命名

检索不到依据的说法，不猜、不编，也不写成「科学家认为」「研究表明」。

点名缺什么、为什么缺：缺的是数字、因果，还是某一人群的适用边界；已查过哪些来源仍没有。然后交用户决定：

- **降级为类比**：画面可以用，但旁白级短句必须标明这是比喻，不把它说成事实。
- **删去**：不进 `beats`。

核查不通过的知识点不进 `beats`。

## 3. 来源冲突：只用一个源

多个权威口径打架时：

- 取**单一可核验来源**。数字不混用：取 WHO 的数，就不把卫健委或其他机构的数补进去。
- 知识卡**点名冲突**，并写取舍理由（更新、更贴本期人群、口径定义更清楚）。
- 检查所取说法与**同一机构的其他文件**是否自洽。同一机构自己打架，按下面的保守表述处理。
- **无法判定就用保守表述**。写「明显升高，但不等于一定会发病」，不写「完全等同」或「一定不会」。

## 4. 落地到 `script.json`

`sources` 是知识卡的留档，不再是空数组。最小结构：

```json
"sources": [
  {
    "claim": "长期高压会让动脉壁变厚变硬",
    "source": "《中国高血压防治指南（2024 年修订版）》",
    "conclusion": "血压长期偏高，血管壁会变厚、变硬，心脏要更用力才能把血推出去",
    "verdict": "通过",
    "quote": "坐位安静休息至少 5min 后，测量上臂血压，上臂应置于心脏水平。",
    "url": "https://www.kepuchina.cn/article/articleinfo?business_type=100&ar_id=531737",
    "checked_at": "2026-10-28",
    "reviewer": "",
    "reviewed_at": "",
    "analogy": "像长期撑大的水管，管壁被越撑越僵",
    "conflict": ""
  }
]
```

| 字段 | 必填 | 含义 |
|---|---|---|
| `claim` | 是 | 本期要说的论点，一句话 |
| `source` | 是 | 单一可核验来源；降级为类比时写「无可靠来源」并在 `conflict` 说明已查过什么 |
| `conclusion` | 是 | 一句话结论，即画面短句要表达的意思 |
| `verdict` | 是 | `通过` / `常识表述` / `降级为类比` / `删去` / `待核查` |
| `quote` | 判通过时必填 | 来源原文摘录，逐字，不改写；`audit.py` 会拦空值 |
| `url` | 判通过时必填 | 能点开核对的链接；PDF 写到具体文件 |
| `checked_at` | 是 | 检索日期 `YYYY-MM-DD` |
| `reviewer` | `通过`/`常识表述` 必填 | 签字人。AI 只能核到 `待核查`，填这里才叫通过 |
| `reviewed_at` | 否 | 签字日期 `YYYY-MM-DD` |
| `analogy` | 否 | 一句话类比或可视化建议 |
| `conflict` | 否 | 冲突了哪几家、取舍理由、或缺口是什么；`待核查` 写清缺什么 |

规则：

- `beats` 里每一条医学论断（短句、数字、因果）都要能回溯到一条 `verdict` 不是 `删去` 的 `sources` 条目。对不上的不进 `beats`。
- `verdict: 删去` 的条目留在 `sources` 里作为记录，不出现在画面和 `beats`。
- `verdict: 降级为类比` 的，画面必须让人看出是比喻，并在同一拍补回真实机制。

## 5. 谁来核：两段式

核查拆成两段，缺一段都不算过。

**第一段 · AI 检索留证**（`story.js` 定稿前）

- 逐条论断检索，只取单一权威来源（指南原文、卫健委文件、学会共识、可核验论文）。
- 把**原文摘录**抄进 `quote`，链接写进 `url`，检索日期写进 `checked_at`。
- **`quote` 一律用中文原文**：优先卫健委文件、国家/行业标准、学会指南、科普中国这类中文出处；外文来源（NIDDK、ADA、EASL 等）要另找中文等效来源来引，找不到就标 `待核查`，不把英文原文塞进 `quote`。看片的是中国老人，签字的人也不该在核稿时先做一次翻译。
- AI 只允许把结论判到 `通过` / `降级为类比` / `删去` 之外再加一个 `待核查`：**凡是没取到原文、或原文与画面措辞有出入的，一律 `待核查`，不许默认通过。**
- 判 `通过` 但 `reviewer` 为空的，`audit.py` 不拦结构，`qacheck.py` 会在报告里写「N 条已核，待人工签字」。

**第二段 · 人工签字**（发布前）

- 人只看两件事：这段 `quote` 是否真的支持这句 `conclusion`；这话对着老年观众说出来是否会造成误读。
- 认可就把名字和日期填进 `reviewer` / `reviewed_at`。不认可就改 `verdict` 或改画面文案。
- **没有签字的 `通过` 不算通过**，`topics.json` 不能改成 `done`。

为什么不让 AI 直接判通过：模型最容易犯的错是来源与结论错配——链接真是权威的，但它支持的是另一句话。所以 `quote` 必须逐字留档，让人能在 10 秒内核对，而不是重新检索一遍。

## 6. 怎么签字：三行命令

签字不看一眼 `script.json`，用可视化页签。

```bash
# 1. 生成签字页（单文件、离线可开）
python3 pipeline/factcheck_page.py ep002-blood-sugar-report ep003-hypertension \
    ep004-lipid-report -o review/factcheck-signoff.html

# 2. 浏览器打开 review/factcheck-signoff.html，每条选一个动作，右下角导出 json

# 3. 回填并留痕（会写 reviewer / reviewed_at，并在 out/qa 生成复核记录）
python3 pipeline/apply_signoff.py factcheck-signoff-2026-10-28.json
```

整期一次认可、不必逐条点网页时，直接在对话里确认，然后：

```bash
python3 pipeline/apply_signoff.py --episode ep002-blood-sugar-report --by 用户 --sign-all
# 待核查的条目要一并转「常识表述」再签，加 --common
```

两种入口写出的 `reviewer` / `reviewed_at` / 复核记录完全一致，区别只是逐条判断还是整期认可。

每条只判断两件事：`quote` 是否真的支持 `conclusion`；这话对老年观众会不会被误读。四个动作：

| 动作 | 含义 | 回填结果 |
|---|---|---|
| 签字认可 | 来源对得上，可以这么说 | 写 `reviewer` / `reviewed_at` |
| 保留为常识表述 | 原文取不到，但这属于通行常识，愿意背书 | `verdict` 改为 `常识表述` + 签字 |
| 需改文案 | 说法比来源强，或容易误读 | 不动 `verdict`，把意见写进 `conflict` 并列进复核记录 |
| 建议删去 | 这句不该出现在画面上 | `verdict` 改为 `删去` |

`常识表述` 是给「数字和因果没原文、但属于常识」留的档位，同样必须有人签字，`conflict` 里要写清缺的是哪条原文。它比 `待核查` 硬：`待核查` 可以永远挂着，`常识表述` 没人签字就一直算欠账。

已对外发布、画面不再改动的期次，在 `script.json` 顶层加 `factcheck_legacy`（带 `since` 与 `reason`），`audit.py` 跳过其旧格式 `sources`，`qacheck.py` 报告里标「已归档」。这是显式豁免，不是暗门。

## 7. 口语化不得牺牲精度

面向老人要口语，但口语化只允许在**句式**上做减法，不允许在**信息**上做减法。三不损：

| 不许 | 为什么 | 换成什么 |
|---|---|---|
| 不丢限定词 | 「10% 以上/一部分人/可能」是这句话的边界，删掉就变成承诺 | 句子太挤就先拆句、换拍位，不要删限定 |
| 不换术语 | 「纤维化也能退」比「逆转纤维化」更含糊：看不出是什么在变，也没更好懂 | 保留专业词，把解释放在同一拍的另一句或名牌里 |
| 不并阈值 | 7%–10% 缓解脂肪性肝炎、10% 以上逆转纤维化，是两档 | 一档一句；字数装不下就只留一档，别把两档揉成一句 |

**反推测试**（每条文案写完后做一次）：把画面句补全成一句完整陈述，看它能不能逐个对回 `sources.conclusion` 的四件事——对象、数值、方向、限定。对不回去，就是这句为了顺口丢了东西；不是改回去，是换一种既顺口又不丢信息的分句方式。

真实案例（第 5 期 `weight` 拍，2026-10-28）：

| | 文案 | 问题 |
|---|---|---|
| 改前 | 减 10%，炎症和纤维化也能退 | 把 7%–10%（炎症）与 10% 以上（纤维化）两档并成一句；「退」替代「逆转」，看不出变的是什么 |
| 改后 | 减 10% 以上，可以逆转纤维化 | 与来源同句；代价是炎症那档只留在画面标签「减重：5% / 7%–10% / 10%」里 |

这一拍共 9.4 秒，第三档只剩 2.3 秒阅读窗口，塞不下第三句。**宁可少说一档，也不把两档并成一句**——少说一档是漏，并成一句是错，漏可以在标签里补，错会跟着成片发出去。

**机器关卡**：`pipeline/audit.py` 的 `lint_copy()`。

- 硬伤：`一定能/肯定会/根治/永久/百分之百` 这类保证性承诺，直接进 `validate_script()`，`qacheck` 判失败。
- 提示：术语被压成单字（`也能退`）、定量结果说成必然（有数字 + 就/也/都 + 效果动词，却没有 `以上/约/部分`）、一句里出现两个阈值。这些出现在 `qacheck` 报告的「文案精度」行，要人看一眼。
- 单句确属必要，可在该行加 `"copy_ok": "理由"` 显式豁免；没有理由的豁免等于关警报。

启发式规则只抓句式，抓不到「这档信息被悄悄省略了」。省略必须写进 `sources.conflict`，让下一个人看得见。
