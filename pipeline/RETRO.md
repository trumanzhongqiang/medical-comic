# 复盘：第 2 期《血糖报告》

2026-11-04。从 3 分 57 秒砍到 1 分 40 秒，中间返工六轮。这份记录只写**能复用的东西**：为什么返工、以后怎么一开始就做对、交付前按什么顺序自检。

一句话结论：这一期的返工没有一次是技术问题，全是「**先决定讲什么，还是先决定怎么说**」的顺序错了。技术坑只有三处，且都是一次性修好的。

## 一、六轮返工，各一条根因

| 轮 | 用户反馈 | 当时的处置 | 真正的根因 |
|---|---|---|---|
| 1 | 「51 秒到 1 分 11 秒删掉，看不懂没意义」 | 删了一整段 | 写的时候按「知识点全」铺，没有先定「这期只讲几件」 |
| 2 | 「打架不是合适的比喻，不如直接用疑问句开头」 | 换开场 | 想用比喻制造亲切，结果比喻本身要额外解释，比问题还长 |
| 3 | 「你这里面还是用到了账本的概念」 | 改掉显性词 | 只查了名词「账本」，没查隐性动词「记 / 攒 / 攒下来」 |
| 4 | 「配音里还是有账本」 | 全片重配 | `gen_voice.py` 遇已有 wav 会 skip，字幕改了、声音还是旧的 |
| 5 | 「字幕有点靠上，应该跟头像圆心同一水平线」 | 改 `SUB` 的 cy | 版式常量散落，头像尺寸和字幕基线各写一份 |
| 6 | 「太精炼了，听不懂」 | 15 句 / 100 秒 | 压缩时先砍句长，正确顺序是先砍知识点 |

第 6 轮最关键：把 3 分钟压进 1 分半有两条路，我选了错的那条。**砍句长** = 每句只留结论，听起来像提纲；**砍知识点** = 只讲三件事、每件讲透，长度自己就下来了。前者是「说得更快」，后者是「讲得更少但更清楚」，只有后者能过。

## 二、写文案的顺序（下次照这个走，别再试错）

1. **先列知识点清单，写进 `beats.src.json` 之前就定死**：这一期只讲 3 件，每件一句话写清「是什么 / 为什么 / 跟她什么关系」。超出三件的，整段删掉，不压缩。
2. **每件配 4–5 句，句均 5 秒左右**：一句只推进一步，但一句里至少带上「为什么」或「在哪儿」，不能只有结论。检验办法是把它念出来——像电报就重写。
3. **开场三句**：疑问句（把她的困惑原样问出来）→ 给两个对象起名字 → 一句话说清各是什么。不要比喻，不要铺垫，不要自我介绍。
4. **主体一律「现象 → 为什么 → 所以」**：两个指标对不上这种双向问题，两边各走一遍完整推导，各给一句结论（「问题其实在饭后」/「是刚冒头，得当回事」）。只讲「一个高一个低」，观众记不住。
5. **画面给推导留位置**：结论要能在画面上看见——平均值那页画一条「平均」虚线，压在锯齿峰中间；「最近才高」那页在曲线末端画虚线圈。**先想好这条证据长什么样，再写那一句旁白。**
6. **收尾**：一句「怎么办」的具体动作（再查一次饭后两小时），一句「拿不准就带给医生」，然后封面点题。封面不写总结口号，写两个名字各自代表什么——「空腹看那一刻，糖化看三个月」。

每期规模参考：3 个知识点 / 9 拍 / 15–16 句 / 95–105 秒。这是「1 分半讲透」的实测配比。

## 三、六条判据，不通过就别往下走

1. **比喻**：全片禁用「账本 / 记账 / 攒 / 打架」这类要先建一个模型再往里填数的说法。糖化就说「三个月的平均」。查的时候要查**动词**，不是只查名词。
   ```bash
   grep -nE "账|记|攒|欠|打架|考试|积分" episodes/<slug>/voice/text.txt
   ```
2. **多音字**：`量 / 数 / 差 / 还 / 转 / 冲` 不赌 TTS。写法上直接绕开（「量的是」→「看的是」，「量是固定的」→「两个钟头后再抽血」）。改词比改拼音稳，换音色也不会错回去。
3. **改一句就要重配那一句**：先把 `voice_src/vNNN.wav`（以及 `voice/vNNN.wav`）挪走再跑 `gen_voice.py`，否则字幕新、声音旧。
4. **配音必须转写核对**，不能只看字幕。拼一条旁白核对轨再转写：
   ```bash
   cd episodes/<slug> && python3 - <<'EOF'
   import json, subprocess
   tr = json.load(open('voice_track.json')); dur = json.load(open('script.json'))['duration']
   args = ['ffmpeg','-y','-v','error']; fc = []
   for i,e in enumerate(tr):
       args += ['-i', e['file']]; ms = int(round(e['t']*1000))
       fc.append(f"[{i}:a]adelay={ms}|{ms},apad=whole_dur={dur}[a{i}]")
   fc.append(''.join(f'[a{i}]' for i in range(len(tr))) + f"amix=inputs={len(tr)}:normalize=0[m]")
   args += ['-filter_complex',';'.join(fc),'-map','[m]','-ac','1','-ar','24000','out/narration_check.wav']
   subprocess.run(args, check=True)
   EOF
   # 然后对 out/narration_check.wav 做一次整轨转写，逐句对文案
   ```
5. **字幕与头像对齐**：`SUB` 的中线取 `NARR_CY`（头像圆心 1137），整块 `translateY(-50%)`，一行两行都不挪。改头像尺寸必须同步改 `NARR_CY`。
6. **画面比声音早半拍**：出场窗口前沿压在该句出口之前（`on()` 比例 0.02–0.35），别等句末才亮。

## 五、三处技术坑（已修，记下别再犯）

- **`on(a, b)` 的 b 是结束点，不是时长**。`on(0.72, 0.14)` 得到负时长，元素永远不出现，画面上就是「少了一样东西」。排查「对勾/箭头没出来」先看这里。
- **一拍超过两句不用 `later()`**。它的进度按「当前这句」重置，一拍三句时元素会在换句瞬间消失再淡回，看着闪一下。三句以上一律 `on()`（按整拍推进）。
- **帧序列命名**：Remotion `--sequence` 出 `element-0000.jpeg`，`compose.py` 认的是 `frame_%06d.jpg`，不匹配会静默变短片。已在 `render_remotion.py` 里加了渲染完自动改名，别手动删这段逻辑。
