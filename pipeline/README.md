# 流水线说明

> 开工前先读 `pipeline/RETRO.md`：那是第 2 期六轮返工换来的教训，写文案的顺序、禁用比喻、配音核对和交付自检清单都在里面。本文件是操作手册，RETRO 是「为什么这么做」。

## 组成

| 文件 | 作用 |
|---|---|
| `engine.js` | 确定性动画引擎：关键帧、路径、相机、剪纸层次、文字审计、品牌头像和既有图形 |
| `factcheck.md` | 医学论断进 `beats` 前的核查关卡：知识卡、缺口命名、单源冲突、`sources` schema、AI 留证 + 人工签字两段式 |
| `factcheck_report.py` | 打印签字单：逐条 claim / verdict / 原文摘录 / 签字人；`--pending` 只看待签与待核查 |
| `factcheck_page.py` | 生成单文件签字页（可离线开、勾选有进度、导出 json），一条卡片=一条 sources |
| `apply_signoff.py` | 把签字页导出的 json 回填进 `script.json`（写 reviewer / reviewed_at，改 verdict），并在 `out/qa` 留复核记录 |
| `audit.py` | 节拍结构、阅读时间、音效引用、字号、安全区、文字碰撞、禁则折行、`sources` 结构与 verdict 枚举、文案精度（`lint_copy`：绝对承诺 / 术语压成单字 / 定量说成必然 / 一档并一句）检查 |
| `render.py` | Playwright 逐帧截图：1080×1440 @2x，校验时长、字体和图片资源 |
| `make_sfx.py` | 生成「空灵音阶」音高层素材（F 大调五声：铃/拨弦/跑动/闪烁/低频），自制无版权风险 |
| `compose.py` | 帧序列 + BGM 包络 + 动作音效（含 `sfx/` 自制池与 `sfx_ext/` 外部素材池）；两阶段 loudnorm 出音频母线，按编码后真峰迭代限幅，再封视频 |
| `build_sfx.py` | 按 `sfx.plan.json` 给画面动作配音效：一页里几个动作就几个声音（`at` 是拍内比例，对应 Art 里的 `on()/later()`），`import_cues.py` 优先用它，没有计划的期退回 `sync_sfx.py` |
| `sync_sfx.py` | 把动作音效钉回每拍起点：`t` 取拍起点，`lead` 取素材实测起音位置（先跳过前导静音），`import_cues.py` 每次导入都会调用 |
| `check_sfx_sync.py` | 音效对齐质检：按 `script.json` 摆一条纯音效轨，逐个量起音相对拍点的偏差，超过 0.1 s 就是没对齐 |
| `peek.py` | 多时点或逐拍布局预览，输出 `out/qa/peek_*.png` |
| `qacheck.py` | 技术指标、逐拍布局、手机尺寸联览、黑场、冻帧、响度和素材许可 |
| `usage.py` | 从当前会话日志汇总模型与 token，写入 `usage.json` |
| `new_episode.py` | 新一期脚手架（模板 + 选题登记） |

## 标准循环

```bash
python3 pipeline/new_episode.py ep012-xxx "标题"      # 建目录（只需一次）
# 1) 写 script.json：beats、学习目标、医学来源、动作音效
# 2) 写 story.js：同一持续世界，不用整屏淡出掩盖换场
python3 pipeline/peek.py episodes/ep012-xxx --beats --strict
python3 pipeline/render.py episodes/ep012-xxx --fps 30   # 连续运动预览
python3 pipeline/render.py episodes/ep012-xxx --fps 60   # 发布帧（canvas 期）
python3 pipeline/render_remotion.py episodes/ep003-hypertension   # Remotion 期：出同样的帧序列
python3 pipeline/compose.py episodes/ep012-xxx
python3 pipeline/qacheck.py episodes/ep012-xxx
python3 pipeline/usage.py episodes/ep012-xxx
```

局部修补：`render.py <ep> --from 12 --to 20`。帧号全局连续，修补前必须确认目录没有旧版多余帧；`compose.py` 会读取完整编号序列。

## 关键约定

- `script.json.duration` 必须等于 `story.js` 的时长，否则渲染直接失败。
- **音效跟着画面动作走，不是一拍一个**：`episodes/<ep>/sfx.plan.json` 按场景写动作（`at` 拍内比例 + 音效名 + 力度），一页 2–4 个声音，平均三秒左右一个。只给「换页」一个转场音会显得片子很静、音效也不贴画面（相机页没有快门声就是这么来的）。拍内 `later()` 类元素按第二句字幕的估计位置填，误差控制在一个动作宽度内。
- **音效表必须跟着时间轴重钉**：节奏一改（重写文案、`--gap`/`--lead` 变了），`script.json.sfx` 不会自己动，整张表停在上一版时间轴上。第 2–5 期重做时就是这么飘的，最多飘出 26 秒，听感是「动画都放完了，声音才来」。现在 `import_cues.py` 每次导入都会调 `sync_sfx.apply()`：`t` = 该拍起点，`lead` = 素材实测起音位置（前导静音先跳过，让真正出声的那一下落在拍点上）。改完跑 `pipeline/check_sfx_sync.py <ep>` 量一遍，偏差应在 0.1 s 内。
- 新期使用 `beats`：每拍包含目的、屏幕文案、首次对象、动作、转场和音效引用。动作要么指定 `sfx`，要么明确 `silent`。
- 先实测 BGM，再填写 `music.bpm / offset / beats_per_bar / sync_tolerance / hard_cues`。普通音效落在拍点，标题、机制转折和结尾等 `hard_cues` 落在小节线；动作的 `t` 必须与引用音效完全一致，同一拍不叠两个音效。
- `lines` 用 `{text, start, end}` 给每句独立的阅读窗口，不再固定副句晚 1 秒；`visuals` 的 `start/end` 控制首次名牌展示，通常留 2–4 拍。旧期纯字符串 `lines` 仍可审计。
- 名牌跟随所指对象与镜头，放在对象旁并加引线；同一时刻只留一条。文案只解释画面正在证明的动作，不用字幕提前否认尚未演出的说法。
- **图文对应（第 3 期 v4 起是硬规则）**：字幕不能孤零零挂在顶上，得让人一眼看出它在说画面里的哪一块。两种实现：
  - 画布期（2/4/5）：`F.note` 在被指对象上画脉冲圈（先垫一圈纸色再描色，落在深色物体上也看得见）；`F.captionLink` 从字幕底部画虚线，接到「先遇到的那个点」——目标在卡片上方就直连目标，否则接名词卡上沿，再由卡片自身的引线落到对象，形成「字幕 → 卡 → 物体」一条链。
  - Remotion 期（3）：解说卡直接定位到当拍主角旁边，卡上带词条章，卡边到焦点画虚线加脉冲圈，字幕不再单独占顶部一条。
  - 名牌表（如 `NOTE_SPECS`）提到模块作用域，`notes()` 和 `captionLink()` 共用同一份坐标，避免两处算出来的位置不一致。
  - 名牌的显示窗口对齐到它所属那一拍（`start/end` 取该拍的 `start/end`），不要只覆盖 2–4 拍：否则一半以上的时间画面没有指向物，字幕又变成孤立的顶部一行。目标点出画（`x<-80 / x>1160 / y<300 / y>1220`）时名牌和圈一起跳过，不做边缘钉住。
- **版式系统（第 3 期 v6 起，Remotion 期先落地）**：全片共用一个固定版式，所有期都照这个来，不再一片一个构图。
  - `remotion/src/layout.tsx` 是版式的唯一来源：`PaperBackdrop`（米白纸 + 点阵 + 边缘彩色纸片）、`EpisodeTag`（左上橙胶囊「医学科普漫画 · 第 N 期」）、`Rule`（y174 细线）、`BigTitle`（y196 起、74px 黑体加粗、一行）、`SubtitleBand`（y1000、x286、宽 730、两行）、`Chip`（名词章）、`Goose`（品牌形象白鹅医生）、`FootNote`（免责声明）。
  - 分区：页头 70–280、主体区 300–972、口播字幕 1000–1160、形象 1030–1360、免责 1370。主体区里的一切动作都必须落在 300–972 之内，不许压标题、不许压字幕。
  - **字幕对齐头像圆心**：`SUB.cy = NARR_CY = 1137`，字幕整块用 `translateY(-50%)` 以这条线居中，一行两行都不挪。改头像尺寸要同步改 `NARR_CY`，别让字幕单独飘在上面。
  - 字幕两行制：正在说的那行墨色 + 关键词珊瑚红，刚说完的那行 42% 处转灰（`#9C9484`）。关键词仍用 `**词**` 标。
  - 图与字的对应靠名词章：`Chip` 贴在当拍主角旁边（`chipAt` 手写坐标），一条虚线指回对象并在焦点画脉冲圈。名词章只在「有具体名词」的拍子挂（约一半），纯论述的拍子不挂，避免整片都是气泡。
  - 品牌形象是**品牌头像**（`Narrator`）：完整原图放进圆形墨蓝边框，固定站在字幕左侧，下方小字「医学科普漫画」；说话能量按句内相位起落（句首轻、中间满、句尾收），驱动外圈微光和右侧三道声波弧。它不参与机制演示，只承担「有人在讲」这层关系。
  - 头像全片只在底部一处，左上角只放栏目章。片尾不再重复放小头像，改为居中放大一次。

### 版式 v3（2026-10 起，四期统一）

第 3 期 v11 之后，去掉「一片一个构图」，改成一套网格 + 一种字幕规则，四期共用。唯一来源是 `remotion/src/shell.tsx`。

| 分区 | 坐标 | 放什么 |
|---|---|---|
| 页头 | y 40–96 | 栏目章（左上）+ 段落章（右上） |
| 细线 | y 174 | — |
| 主题 | y 190–268 | 全片固定一行，宋体加粗 |
| 图解区 | y 292–832，x 56–1024 | 一拍一个主角，占满整幅；网格列心 200 / 540 / 880，行心 372 / 562 / 752 |
| 注解条 | y 872–972，全宽 968 | 左：名词章或数值章；右：一句条件/范围，字宽超 21 就自动缩字号，永远一行 |
| 口播字幕 | x 292，宽 732，**中线 y 1137**（整块以头像圆心上下居中） | 旁白原文，最多两行 |
| 品牌头像 | y 1020 起，size 150，圆 1062–1212 | 读旁白，圆心 1137 |
| 免责 | y 1348 | — |

三条硬规矩：

1. **图解区左右顶满**：任何图形组合都要在 56–1024 里排均衡，不允许只占左半边、右边留白。
2. **标签贴着对象**：对象下方 14px，同一组元素共用一条基线；不许悬空飘字。
3. **断行只断在标点后、虚词前**：按真实字宽（汉字 1、数字 0.56、空格 0.34）计算；两行宽度尽量相等；行尾不留标点；放不下两行就整句缩字号，绝不掉到第三行。

断行实现在 `remotion/src/wrap.ts`，单独成文件是为了**不渲染也能体检**：

- 代价式选点：`|左行宽 − 半句宽|` 是底分；标点之后 +0、虚词之前 +1.2、别处硬断 +8；劈词 / 单字行 +80；行首是「的 / 了」+3.5；「最 / 更 / 很 / 太 / 超」后面 +40。
- `GUARD` 词表（血压、低密度、葡萄糖、数量、以后……）用来判「劈词」：断点落在一个词中间就重罚，所以不会再把「数量」切成「数 / 量」。
- 体检命令：`node remotion/scripts/check_wrap.mjs episodes/<slug> ...`，逐句打印断行结果，标出劈词、掉三行、两行过分不均、整句缩字的位置。改词表或改文案后先跑它，再去渲染。

### 底噪与旁白的让位（2026-11 起）

- **`bgm_volume` 是绝对电平，`bgm_envelope` 只描写形状**（2026-11-03 修）：以前 `envelope()` 的数值被直接当绝对增益用，有包络时 `bgm_volume` 被**完全忽略**——所以前四期写 0.65、第七期写 0.34，实际都在按包络里的 0.52 播，调小音量从来没有生效过。BGM 源是 −11 dB RMS，0.52 相当于 −17 dB，和人声的 −21 dB 只差 4 dB，人声当然听不清。现在 `volume = envelope(形状) × bgm_volume`，统一 `bgm_volume 0.10`、包络平线 `[[0,1],[dur,1]]`：BGM 总线约 −34.5 dB，比人声低 13 dB，说话时侧链再让 5 dB，差到 18 dB。
- **BGM 做避让人声的 EQ**：`highpass 70` 去掉轰鸣、`350 Hz −2 dB` 去浑、`2400 Hz −4.5 dB` 挖掉人声最吃紧的一段。只压音量不挖频段，BGM 会在 2 kHz 附近继续糊住字。
- **BGM 电平全程恒定**：包络拉平成一条线。以前用「弱→强→更强→回落」的包络，观众听到的就是「说完话音乐又涨上去」，和侧链叠在一起就成了忽高忽低。
- **侧链只做轻微让位**：`voice_ducking` 统一 `threshold 0.06 / ratio 2.0 / attack 30ms / release 700ms`。旧参数（threshold 0.02 / ratio 8 / release 280ms）在近满铺的人声下最深能压 19 dB、0.28 秒就回弹，听起来就是「一说话就掉、一停就涨」；新参数峰值处只压 5–6 dB，回弹近 0.7 秒，听感是一条平线。
- 改完只重跑 `compose.py` 即可（帧不动）。

### 已有音频的期怎么接进来（import_cues）

有的期先录好音（`cues.json` 里每句都有真实 `t/end`），这时不能再用 `build_beats.py` 重排拍长，否则对不上人声。用：

```
python3 pipeline/import_cues.py episodes/<slug>
```

- `cues.json`：每句的时间与字幕原文，只读。
- `beats.src.json`：人写的画面表，每个拍写 `cues: [序号…] / scene / note`，`timing: "cues"`。
- 脚本按 cue 边界算拍点（画面比人声早 0.2s 进场），subs 用 cue 原文，`voice` 沿用已有轨道，然后发 Remotion 数据。第 7 期就是这么接的。

### 一页只有一个主角（2026-11-03）

观众「眼睛不知道看哪里」「跟不上」，几乎都是同一页上的字打架，而不是字太多。规矩：

- **顶部只留一级信息**：期号章 + 大标题。段落章（`SectionTag`）整条删掉——它和期号章挤在同一行，换段时闪一下，多数时候只是多一行灰字。大标题在 9 秒后退到 0.75 的浓度（只在开头承担交代主题的活）。
- **注解条降成注脚**：原来是 968×100 的描边方框加一句长文，等于在图解之外又插了第三块「主体」。现在只是图解区下方一行细字（名词 34 号强调色 + 半句 26 号灰字，无框无底），而且要等到这一拍 55% 之后才出现（`noteP`）。
- **每页视觉块 ≤ 4**：腺体 + 箭头 + 四颗胶囊 + 两条标签 + 脚注 + 字幕 = 九件东西，没人跟得上。超了就按「这一拍要说的那一件事」删——讲全身快慢时不再画腺体，讲重量时不再重复克数，讲症状时不再画「箭头指向」。
- **画面里的说明不复述旁白**：一页里同一句话说三遍（画面小标题 + 注解条 + 字幕）是最常见的乱源。写完之后对照 `note.body` 和当前字幕，同义就删画面里那条。
- **注脚只放关键词，不放句子**：`note.title` 是一个名词或一个数（34 号、强调色），`body` 控制在十个字以内。它的活是「给这一页那个东西起名字」，不是把旁白再写一遍——凡是和画面上已有胶囊同义的，直接 `kind: "none"`。第五期 18 拍留 11 条、第六期 17 拍留 8 条，空着的地方比填满的地方好看。
- **示意图要有一个实物锚点**：单独一根趾头会被看成手指，底下接一段脚背才成立（`Gout.tsx` 的 `Toe`）；孤零零一根针不像针，旁边给一个装着尿酸的圆才像「析出来」。抽象图形至少要和一件观众认识的东西同框。
- **一排胶囊等宽等距**：`Chip` 支持 `w`，同一组必须给同一个 `w`，并落在 `ROW` 行心上。人像的「抖/热」小闪电贴着脑袋右上角（`Person` 里改过坐标），不再飘到标题边上像两笔乱线。
- **骨架先摆出来，内容跟着旁白一件一件出**：一页里的胶囊/卡片整体在 2.5 秒内出现，但组内的每一项间隔不小于 0.14（整拍比例）——报到一个亮一个，而不是一起撒出来。多句一拍时用 `stage` / `su` 让后一句的元素晚起。

### 讲给老人听：慢、细、一句一句来

这一版的节奏是照着「上了年纪、第一次听说这个病」的人定的，不是照着刷短视频的人定的。

- **旁白要展开，不能发电报**：「激素太多，全身被迫加速」这种句子自己看得懂，念出来没人跟得上。每句都要交代三件事——这是什么东西、它在哪儿、这个动作是什么意思。比如不是「甲减是脚不踩」，而是「甲减正好相反，油门松开了，脚几乎不踩，全身都慢下来」。
- **从关切开始**：第一句不是定义，是「最近是不是老觉得累」。先让人对上号，再讲机制。
- **一句只推进一步，但不能只有一步**：一句话里除了结论，还要带上「为什么」「在哪儿」「跟她有什么关系」。比如不是「糖化是过去三个月的一本账」，而是「它不是哪一天、哪一顿饭的数，是把过去三个月平均下来」。尺度大概是每句 20–25 字、五秒上下，一拍 12–20 秒；句子再短就是电报，再长一口气念不完。第 2 期按这个尺度重写后 14 句 / 84 秒，句均 5.0 秒。
- **要短就砍知识点，不砍解释**：把三分钟压成一分半，做法是「这一期只讲三件事」，不是「把三分钟的话说得更快」。先定这一期讲哪几个点，每个点配四到五句讲透（是什么、为什么、跟她什么关系），剩下的整段删掉。第 2 期从 42 句压到 14 句时走过一次弯路：句子被压成「空腹只管抽血那一下，糖化是三个月的平均」这种电报，字少了、听不懂了；改回展开叙述、只留三个知识点，才既短又听得懂。
- **句间留白 0.70 秒**（`build_cues.py --gap`）：上一句说完，留大半秒让人咽下去，再接下一句。片头 1.2 秒。第七期从 0.42 加到 0.70 后，全片 225s → 236s，一拍平均 7.6 秒。
- **一句一份画面**：第 7 期 31 拍 / 35 句 / 约 3 分 56 秒。以前 28 拍塞 28 句、平均 4 秒一切。多句一拍时，画面按句子推进（`stage` / `su`），第一句给物体和名字，第二句才给动作。
- **字幕按分句拆**：一句话拆成一到两条，每条最多 15 字，字号守住 46 号。整句三十字压两行得缩到 36 号，老人看着吃力；拆开之后读到哪儿跟到哪儿。实现在 `import_cues.py` 的 `split_sub()`。
- **不写术语，写她嘴上的词**：老人听不懂的不是道理，是名词。「糖化血红蛋白」先说「另一个数叫糖化」，把全称留给画面上的化验单去对；「糖尿病前期」说「血糖已经偏高，还没到糖尿病」；「糖耐量试验」说「喝一杯糖水再查」；「近期大量失血」说「刚失过血」；「150 分钟 / 周」说「一个礼拜两个半钟头」。凡是第一次出现的名词，同一句里给一个生活化的说法，不让她去猜。第 2 期先按这条改成口语（36 句 / 178 秒），又发现「说清了但太简略」——每句只丢一个结论，像提纲。
- **改过一句就要重配那一句**：`gen_voice.py` 遇到已有文件会 skip，改完文案必须先把对应 `voice_src/vNNN.wav` 挪走再跑，否则字幕是新字、声音还是旧话。交付前用 `AudioTranscribe` 转写整条旁白轨（拼 `voice/v*.wav`）逐句核一遍，不能只看字幕。
- **不用「账本 / 记账 / 攒」这类比喻**：糖化就说「三个月的平均」，不要说它「记了三个月」「攒了三个月」。凡是需要读者先建立一本账、再往里填数的说法，一律换成直接说平均。第 2 期第一版用「打架」和「账本」，都被否掉了。
- **多音字不要赌 TTS**：`量 / 数 / 差 / 还 / 转` 这类字，合成音色十次里有几次读错，而字幕上看不出来。第 2 期「量的是两段时间」被念成 liàng。写法上直接绕开——「量的是」改「看的是」「算的是」，「量是固定的」改「两个钟头后再抽血，数才可比」。改词比改拼音稳，也不用担心换音色又错回去。
- **两个指标对不上，要把两边的结论各说一遍**：只讲「一个高一个低」观众记不住。每一边都要给「现象 → 为什么 → 所以说明什么」：空腹正常、糖化高，是因为饭后那一两个小时没人测，三个月平均被抬上去，所以问题在饭后；空腹高、糖化正常，是因为高只出现在最近，平均还抬不动，所以是刚冒头。画面上配一条「平均」虚线，让这条推导看得见。
- **结尾封面要拿这两个指标点题**：不是复述「两个数」，而是把两个名字各自代表什么说清楚——「空腹看那一刻，糖化看三个月」。`big` 控制在 13 字以内（超过 11 字会自动缩到 62 号），`sub` 一行放完，超了就会在中间断出一个孤零零的「月的平均」。
- **`on(a, b)` 的 b 是结束点，不是时长**：`on(0.12, 0.42)` 是从 12% 到 42%，不是「从 12% 起、持续 0.3 秒」。写成 `on(0.72, 0.14)` 会得到负时长，元素永远不动，画面上就是「少了一样东西」。
- **一拍超过两句就不用 `later()`**：`later()` 的进度按「当前这句」重置（`su`），一拍三句时元素会在换句那一瞬消失再淡回来，看着像闪一下。三句以上的拍一律用 `on()`（按整拍 `u` 推进），元素出现后就不再退。
- **画面比声音早半拍**：元素出场窗口的前沿要压在该句说出口之前（`on()` 的比例给到 0.02–0.35 之间），不要等到句末才亮——观众听到词、画面还是空的，就是「跟不上」。

新流程（没有现成录音的期）：

```
写 voice/text.txt（一句一行）
~/dev/tts/.venv/bin/python ~/dev/tts/gen_voice.py episodes/<slug>
python3 pipeline/build_cues.py episodes/<slug> --lead 1.2 --gap 0.70
python3 pipeline/import_cues.py episodes/<slug>
```

`build_cues.py` 去首尾静音、排时间轴、写 `cues.json` 和 `voice_track.json`（逐句人声轨道），并把 `beats.src.json` 的 `duration` 一起改掉。

### 文案分层（旁白 / 画面解耦）

- `beats.src.json` 的 `voice` 只写口播：允许连接词、允许因果、按句切开当字幕。
- 同一拍的 `note` 只写画面：`{kind: term|number, title, body}`，`body` ≤ 21 字宽，只放条件、范围、单位，**不复述旁白**。
- 段落章 `sections` 每期 5–6 个，观众随时知道讲到第几步。
- 语速约定：`build_beats.py` 用 `rate`（默认 5.0，四期统一设 4.8）估算拍长；克隆音色偏慢，`make_voice.py` 先全片统一 1.08 倍，单个拍超预算才继续压，上限 1.24。

### 旁白配音

- 每期 `voice/vNNN.wav`：**一句一个文件**，24kHz 单声道；`make_voice.py --write` 在 `script.json` 的 `voice` 里逐句写 `{file, t, gain}`（`file` 相对本期目录，`t` = 该句入点），`compose.py` 就是按这份逐句轨道铺人声的，字段不能省。`voice_ducking` 让人声对 BGM 做侧链，音乐自动让位。
- `python3 pipeline/make_voice.py episodes/<slug> --plan`：打印每拍文本、入点与可用时长，同时写 `voice/text.txt`（编号 + 时间码 + 文本），这份清单可以直接拿去克隆音色平台批量合成。
- 平台导出后按 `v00.wav … v35.wav` 命名放进 `voice/`，跑 `--engine files --write` 写回 `script.json`，再 `compose.py`。
- `--engine say` 只产占位音（系统音色，用来验证节奏与混音），不能当成品交付。
- **本机克隆音色**：`~/dev/tts`（mlx Qwen3-TTS，参考音 `ref/my_voice_dry.wav`）。`gen_ep003.py` 是范例：读 `voice/text.txt` 批量合成；`fit_ep003.py` 去首尾静音 + atempo ≤1.25 压进每拍预算。换一期照抄改路径即可。
- 句子念不完会报警：先压文案，不要靠拉语速硬塞。
- 音效支持 `gain`、`pan`、`rate`、`start`、`duration`、`trim_db`、`lead`。所有音效必须保留可商用许可。
- **`lead`（提前量）**：`t` 永远是动作/拍点时刻，`lead` 表示这条音效从 `t - lead` 开始播放。真实 whoosh 的能量峰值在起音后 0.2–0.7 秒（长气声可达 2 秒），不提前就会「声音晚于画面」。`lead` 上限一小节，起点被截到 0 时由 `compose.py` 自动裁头。
- **两层素材库**：
  - `assets/audio/sfx/` 自制音高层，`make_sfx.py` 生成。BGM 定调后取该调的五声音阶（第 1 期为 F 大调），音高类素材全部锁在调内。
  - `assets/audio/sfx_ext/` 外部真实素材，只用于「无音高」的气声与冲击层。每条必须在 `manifest.json` 记录来源、原始标题、下载地址、许可与 `trim_db`；删除清单里的记录等于丢失许可证据，投稿前要能对上。
- **六层分工**（按动作性质选层，不要都用同一种）：
  - 出现 `pop`、确认 `air-N`、点亮 `shimmer` —— 音高层，负责「音符感」。
  - `run-up/down-*`、`tri-up/down` —— 卡点跑动，一条素材内含 3–4 个音，间隔取 BGM 十六分音符，用于一拍内连响。
  - `air-*` —— 真实 whoosh（短/中/宽/深/长渐弱），负责转场、主体移动与「空灵感」。至少准备 3–4 个变体，同一个 whoosh 不要反复用；实测峰值偏高、感听响度偏低，靠 `manifest.json` 的 `trim_db` 压回统一响度。
  - `sweep-up` / `sweep-tick` / `sweep-bright` —— 外部上行扫频素材。注意它们的峰值在中段、之后衰减，**不能**用来做「蓄力到落点」；那种位置用反向气声（见下条）。
  - `rise-rev` / `rise-rev-bar` / `rise-rev-short` —— 由 `air-fall` 反向裁切得到的真气声蓄力：包络从 -70 dB 单调递增到末尾，长度取 2.60s / 3.117s（一小节）/ 1.56s。`t` 直接放在重音前一拍（或一小节），`duration` 等于素材长度，它的末尾就正好压在 impact 上。
  - `drop` / `air-fall` —— 下行：`drop` 是短促坠落，`air-fall` 是长气声渐弱，用于失效、风险、镜头拉远。
  - `impact-soft` / `impact-deep` / `thump` —— 冲击：受阻与转折用 `impact-soft`，机制崩塌用 `impact-deep`，心跳式落点用 `thump`。
  - 常用组合：whoosh 接下一拍的 `air-N` 铃（`whoosh → 叮`）是解释类视频最典型的揭示手势，铃要放整拍而不是十六分，避免和 whoosh 的尾巴糊在一起；反向蓄力接 impact（蓄力→落点）最强。
  - 音高层保持调内、气声层不带音高，两者不要互换：给 whoosh 加音高会破调，用铃替代 whoosh 会失去空间感。
- **节奏与密度**：单个音效不超过 2 秒；关键音效每 3–5 秒一个，10 秒内不超过 3 个。健康医疗类内容保持克制，不用警报式尖锐音；负面信息用下行与低频表达，不用刺耳高频。
- 不要用 `rate` 拉伸跑动或 riser 素材，会连带改变音高与卡点，需要别的长度就直接在 `make_sfx.py` 里生成。`compose.py` 用独立音效总线短促 sidechain 给动作让位，增益仍按动作力度逐条设置。
- **音效响度**：配置 `music.sfx_normalize: {target_peak_db, intensity_curve}` 后，`gain` 表示「力度」而不是绝对倍数——会先按素材实测峰值把每条拉齐到 `target_peak_db`（第 1 期用 -6.5），再用 `intensity_curve`（0.4）压缩轻重差别。不配这个键则沿用旧的绝对倍数行为。素材原始峰值相差可达 10 dB，直接填小倍数（0.05–0.2）会让音效被 BGM 完全盖住。
- `bgm_envelope` 用 `[秒, 音量]` 控制音乐情绪；BGM 缺失时合成失败，不用静音冒充完成。
- **真峰与编码器**：`loudnorm` 的 `TP` 只管滤镜链内部，成片真峰取决于编码器。ffmpeg 自带的 `aac` 在打击类音效上实测过冲可达 3 dB 以上（母线 -3.3 dBTP → 解码 0.1 dBTP），所以默认用 macOS 的 `aac_at`（过冲约 0.8 dB）。`compose.py` 会先出音频母线 wav，再逐轮「编码一次 → 测解码后真峰」，直到 ≤ `true_peak_max`（默认 -1.8）再封视频，避免为了一个尖峰反复重编视频。可用 `script.json` 的 `audio_encoder` / `true_peak_max` / `limiter_limit` 覆盖。
- 文字通过 `window.__audit()` 返回屏幕坐标，并带 `lineStarts`（每个换行片段的行首字符）。主句至少 64px，解释至少 44px，免责声明至少 36px。闭标点（`，。？！、；：）】》` 等）出现在行首时审计报警，不改排版。
- 转场优先对象原位变化、镜头和路径连续。`fadeIn/fadeOut` 只保留给旧期兼容，不作为新期换场方式。
- 自动质检不能代替逐拍人工复核：仍需确认因果、比喻含义、阅读速度、动作落点和声音同步。
